# Financy v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** entregar a menor versão completa do Financy para portfólio: contas individuais, categorias, transações e dashboard, publicada com Vercel Hobby e Supabase Free.

**Architecture:** aplicação React/Vite no navegador, organizada por funcionalidades, com TanStack Router, Query, Form e Table. Supabase Auth gerencia identidade e nome do perfil; PostgreSQL, Data API e RLS mantêm duas tabelas próprias e executam agregações financeiras. Um repositório público contém frontend e migrations; desenvolvimento e produção usam projetos Supabase distintos.

**Tech Stack:** React, TypeScript, Vite, pnpm, TanStack Router/Query/Form/Table, Tailwind CSS, shadcn/ui, CVA, tailwind-merge, cliente Supabase, PostgreSQL e Supabase Auth. Propostos para verificação: Vitest e Playwright; Lucide para os ícones referenciados no Figma. Versões serão verificadas na execução.

**Spec:** [especificação aprovada e propostas técnicas](../specs/2026-10-14-financy-v1.md). Plano aprovado para execução nativa. Em 2026-10-15, a entrega 1 foi implementada e verificada; entregas 2–6 pendentes. Evidências e ajustes: [registro da primeira entrega](../execution/2026-10-15-financy-base.md).

- “Valores em BRL e apresentação brasileira de valores e datas” (TX-06).

- Cada conta começa sem categorias; `category_id` é obrigatório; nenhuma exclusão de categoria apaga transações.

## Contratos compartilhados

As assinaturas abaixo são decisões para implementação; não representam código já existente.

```ts
// src/features/categories/types.ts
type Category = { id: string; name: string; color: string; icon: string };
type CategorySummary = Category & { transaction_count: number };
type CategoryInput = Pick<Category, 'name' | 'color' | 'icon'>;

// src/features/transactions/types.ts
type TransactionKind = 'income' | 'expense';
type TransactionInput = {
  description: string; kind: TransactionKind; amount: string;
  occurred_on: string; category_id: string;
};
type Transaction = TransactionInput & {
  id: string; created_at: string; category: Category;
};
type TransactionFilters = {
  q: string; kind: TransactionKind | 'all'; categoryId?: string;
  month: string | 'all'; page: number;
};
type TransactionPage = { rows: Transaction[]; count: number };

// src/features/dashboard/types.ts
type DashboardSummary = {
  balance: string; income: string; expenses: string;
  topCategories: (Category & { amount: string })[];
  recentTransactions: Transaction[];
};
```

`amount`, `balance`, `income` e `expenses` são texto decimal canônico, com ponto e duas casas, e não números de ponto flutuante. `occurred_on` é `YYYY-MM-DD`; `month` é `YYYY-MM`. Categorias retornadas em transações vêm da relação atual, não de uma cópia histórica.

Chaves de cache: `['finance', userId, 'categories']`, `['finance', userId, 'transactions', filters]` e `['finance', userId, 'dashboard', month]`. Qualquer mutation financeira bem-sucedida invalida `['finance', userId]`. Não usar atualizações otimistas na primeira versão. Cancelar consultas e limpar o cache ao sair/trocar de conta.

Variáveis do frontend: `VITE_SUPABASE_URL` e `VITE_SUPABASE_PUBLISHABLE_KEY`. Testes usam `FINANCY_DEV_PROJECT_REF`, `FINANCY_TEST_ALICE_EMAIL`, `FINANCY_TEST_ALICE_PASSWORD`, `FINANCY_TEST_BOB_EMAIL` e `FINANCY_TEST_BOB_PASSWORD`, carregadas somente pela configuração de testes a partir de `.env.test.local`. `.env.example` documenta os nomes sem valores reais. Nenhuma variável administrativa usa prefixo `VITE_`.
